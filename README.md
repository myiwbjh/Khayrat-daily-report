# Khayrat EPC 工程日报分析系统

面向伊拉克 Samawah **Khayrat 3,200 TPD 水泥粉磨站 EPC 项目**的工程日报分析系统。系统默认不显示虚构项目数据；导入真实日报后才计算指标。内置数据仅用于演示，并始终显示“示例数据模式”。

本次 PDF 图文与视觉升级、真实日报验收范围及费用授权见 [升级验收记录](docs/layout-vision-review.md)。基础功能检查见 [基础功能验收记录](docs/foundation-review.md)。

## 现有架构：GitHub + Vercel + Supabase

正式用户只需要浏览器，不需要在 Windows 安装 Node.js、Python 或运行开发环境。推荐由管理员完成一次云端部署：Vercel 托管静态前端和 OCR/视觉服务代理，Supabase 提供邮箱登录、Postgres 数据库和私有对象存储。

### 需要准备的账号

1. GitHub、GitLab 或 Bitbucket 账号及本仓库访问权限。
2. Vercel 账号，用于导入仓库和发布公开 HTTPS 地址。
3. Supabase 项目，用于 Auth、Postgres 和 Storage。
4. 可选 OCR/视觉服务账号；仅扫描日报或真实图片识别需要。

### 现有项目维护

继续使用现有仓库和 Vercel/Supabase 项目。修改在独立分支提交 PR；本轮不合并、不改生产数据库、不执行生产部署。

- 已登录时由 Supabase SDK 恢复并刷新会话。首次登录仍需要验证管理员批准的邮箱，不能绕过认证。
- 原始文件保存到现有私有 Storage，结构化数据复用已有表的 JSONB `payload`，不需要本轮增加生产列。
- `supabase/schema.sql` 是历史初始化模板，包含范围过宽的 authenticated 策略，**不能在现有生产项目重新执行**。生产权限应以控制台实际 RLS 策略为准，新增测试环境也应由管理员先审核该文件。
- 如需人工验证生产登录，先核对获准用户、Email Provider 和 Site URL/Redirect URLs。未经批准，不进行生产上传或写入验收。
- PR 分支可能触发现有 Vercel 的 Preview 集成，不能把 Preview 提升为 Production，也不能为其复制生产密钥。本轮没有发出任何部署命令。

### 环境变量

| 名称 | 必需 | 保存位置 | 说明 |
|---|---|---|---|
| `SUPABASE_URL` | 云存储必需 | Vercel | Supabase Project URL |
| `SUPABASE_ANON_KEY` | 云存储必需 | Vercel | 可公开的 anon key；安全性依赖 RLS，不是 service-role key |
| `SUPABASE_STORAGE_BUCKET` | 否 | Vercel | 默认 `khayrat-reports` |
| `ACCESS_CONTROL_REQUIRED` | 建议 | Vercel | 正式环境保持 `true`；AI 接口独立验证真实身份、白名单和 RLS，不受此开关绕过 |
| `AI_FEATURES_APPROVED` | AI 可选 | **仅 Vercel 服务端** | 默认 `false`；仅负责人批准费用与传输后开启 |
| `AI_ALLOWED_USER_EMAILS` | AI 必需 | **仅 Vercel 服务端** | 逗号分隔获准邮箱；空值拒绝全部用户；不能扩大现有 RLS |
| `VISION_PROVIDER` | AI 必需 | **仅 Vercel 服务端** | 免费方案 `groq`；另行授权的付费方案 `openai`；无自动切换 |
| `VISION_MODEL` | AI 可选 | **仅 Vercel 服务端** | Groq 固定 `qwen/qwen3.8-27b`；OpenAI 固定 `gpt-4.1-mini-2025-04-14` |
| `GROQ_API_KEY` | 免费 AI 必需 | **仅 Vercel 服务端** | 用户安全填写，Free Plan 及零数据保留需控制台确认 |
| `GROQ_FREE_TIER_CONFIRMED` | 免费 AI 必需 | **仅 Vercel 服务端** | 默认 `false`，确认账号仍为 Free Plan 后设为 `true`；标记不能自动验证账单 |
| `OPENAI_API_KEY` | 付费 AI/OCR 可选 | **仅 Vercel 服务端** | 负责人安全填写；不得粘贴到聊天或仓库 |
| `OCR_ENABLED` | OCR 可选 | **仅 Vercel 服务端** | 默认 `false`；开启后仍需每次扫描页传输授权 |

不得把 Supabase `service_role`、OCR 或视觉服务密钥放入 `app.js`、GitHub 仓库或任何 `VITE_*`/公开前端变量。`/api/config` 只返回允许公开的 URL、anon key 和功能开关。

### 必须由管理员手动完成

- 创建 Supabase 与 Vercel 项目、执行 SQL、配置 Redirect URL 和环境变量。
- 邀请或批准可访问项目的邮箱用户。
- 决定并配置 Vercel Deployment Protection。
- 如需扫描件 OCR 或真实视觉识别，选择合规服务、签订数据处理协议并配置服务端密钥。
- 上传一批脱敏真实日报，按本文“使用真实 PDF 验收”逐项签字确认识别准确率。

授权完成后可运行不会打印密钥值的部署前检查：

```bash

```

它会检查必要变量是否存在，以及 GitHub、Vercel、Supabase API 是否可达；任一必要条件缺失时返回非零退出码，避免把“配置文件已准备”误报为“云端已部署”。

## 启动

```bash
npm ci
npm run build
python3 -m http.server 4173 --directory dist
```

访问 <http://localhost:4173>。由于使用 ES Modules，不能直接双击 `index.html`。

### Windows 用户

1. 开发机安装 Node.js 24.x 并运行 `npm ci`、`npm run build`；正式用户直接使用网站。
2. 从 [Python 官网](https://www.python.org/downloads/windows/) 安装 Python 3，安装时勾选 **Add Python to PATH**。
3. 下载或解压本项目文件夹。
4. 双击项目根目录的 `start-khayrat.bat`。脚本会启动本地服务器并在默认浏览器打开 <http://localhost:4173>。
5. 在网页中进入“日报录入”测试手工填写；或下载 Excel 模板，填写后回到页面导入。
6. 命令窗口必须保持打开。使用完毕后在窗口按 `Ctrl+C` 停止服务器。

也可以在 PowerShell 中进入项目目录后运行：

```powershell
npm ci
npm run build
py -m http.server 4173 --directory dist
Start-Process http://localhost:4173
```

## 已实现功能

- 导入 UTF-8 CSV、标准 `.xlsx`（读取首个工作表）和一个或多个 PDF 日报，支持多文件合并与重复记录去重。
- 导入工程周报 `.pptx`，从原生 OOXML 提取期号、周区间、全文、表格、备注、车间状态、下周计划、人员、机具、风险/物流、工程量和施工照片；照片保留页码并按车间及“上周/本周”关联，封面、Logo 和装饰资源不进入证据库。
- 自动恢复获准用户的已验证会话，支持续期、显式退出、云端日报读取和非覆盖合并。
- 新增独立“日报对比”页面，默认对比最近两个报告日期，展示施工状态、施工内容、人员、当日/累计工程量、设备状态和问题变化，保留双方来源。
- 按截止日期、车间、工序筛选，并按日报、周报、月报聚合趋势。
- 计算 WBS 加权计划/实际进度、偏差、分单位工程量、人员构成与环比变化。
- 展示主要设备的发运、到货、安装准备状态，以及日报风险和进度滞后风险。
- 识别连续停工并保留日报名称、日期和原始记录证据。
- 导出当前筛选范围的标准化 CSV，并提供中文字段模板。
- 独立“日报录入”页面，支持新增、编辑、查询、删除、字段校验和重复日报提醒。
- 手工录入和批量导入数据持久化到当前浏览器 IndexedDB，并保留 `localStorage` 兼容回退；导入时使用活动级业务键跳过真正的重复项。
- 本地数据 JSON 备份与恢复；恢复时校验格式、记录有效性并跳过重复项。
- 浏览器端生成可直接填写并可被系统重新读取的标准 `.xlsx` 模板。
- 未配置云端时数据只保存在当前浏览器；配置 Supabase 且用户登录后，原始文件和分析数据会同步到项目私有云存储，界面会明确显示连接状态和失败信息。
- PDF 使用同源托管的固定版本 PDF.js 提取多页、中英文和带位置的文本，内置解析器作为离线降级，并将 JPEG、Flate 等由 PDF.js 解码的嵌入图片转换为 PNG；日报、页码、原始文本摘要、来源位置和提取方式随记录保留。
- 浏览器可多选 PDF，也可选择包含子目录的整个日报文件夹；相对路径作为来源保留，原始 PDF 上传到私有对象存储。
- “图片证据”页面支持缩略图、大图、日期/车间/工序/日报筛选、关键证据、忽略、人工改标签、场景、证据类型及日报关联。
- 周报工程量、日报工程量与最新有效工程量 Excel 分来源显示并计算差异，不跨来源累计。工程量 Excel 始终是正式进度计算主源，较新的周报只补充车间、人员、风险、计划和照片并用于核验。
- 图片证据可关联车间进度、设备到货/安装准备、风险和连续停工记录；PDF 原文优先，图片识别仅作补充，冲突时保留原文并标注差异。

## 输入数据结构

CSV 首行或 Excel 首行是字段名。支持以下中文名，也支持代码中定义的英文别名：

| 字段 | 类型 | 说明 |
|---|---|---|
| 日报名称 | 文本 | 证据来源名称 |
| 日期 | `YYYY-MM-DD` | 必填 |
| 施工内容 | 文本 | 日报明确记载的当日施工活动 |
| 车间、工序 | 文本 | 对比和停工识别维度 |
| 计划进度、实际进度 | 数值 | 百分数，可写 `23.5` 或 `23.5%` |
| 实际完成工作量、累计完成量 | 数值 | 兼容旧字段“当日混凝土、累计混凝土” |
| 工作量单位 | 文本 | 如 m³、t、项 |
| 中方人员、属地人员 | 整数 | 现场人员数量 |
| 设备名称、设备状态 | 文本 | 如已发运、已到货、安装准备中 |
| 风险制约 | 文本 | 影响施工或安装的风险 |
| 工作状态 | 文本 | 如施工中、停工、完成 |
| 原始记录 | 文本 | 用于证据追溯的日报原文 |

字段标准化与别名映射位于 `src/analytics.js`，文件解析器采用适配器结构。Excel 模板字段与这些导入别名保持一致。`src/xlsx-writer.js` 在浏览器中生成标准 OOXML 文件，不需要上传模板或数据。

## PDF 与图片证据流程

1. CSV、Excel 和 PDF 各自由适配器解析，输出相同的标准日报对象；导入前先显示记录、重复项、图片和错误预览，确认后才通过事务写入，后续分析共用一套逻辑。
2. PDF 优先加载构建时打包的同源 PDF.js 和 worker（包含浏览器兼容补丁），按页提取文字和坐标；不可用时降级到支持未压缩或 `FlateDecode` 内容流的内置解析器。无法映射的关键字段进入 `reviewFields`，不会补造数值。
3. PDF.js 解码的图片转换为 PNG，在云端模式上传到私有 Storage；云端持久层只记录唯一 `imageId`、对象路径、文件名、页码、页内顺序、邻近文字和日报关联。
4. PDF.js 保留文字/表格列、向量边框及图片坐标；按同栏施工段和明确图注关联各图。重复页眉保留在布局中，连续图块合成为照片；多工序照片保留候选活动，具体工序须复核。无布局的降级解析禁止整页关联。人员汇总只计项目当日口径，工程量必须有明确当日/累计及单位。
5. 未调用视觉服务时仅显示配对日报原文，场景为“无法判断”。授权后的 `ImageAnalysisProvider` 仅发送图片 ID、同意标记与所授权服务商；后端验证身份、账号白名单、证据 RLS 与私有 Storage 权限，再发送一张图及该图对应原文至明确授权的 Groq 或 OpenAI。更换平台需重新授权。Groq 免费方案单图间隔约一分钟，可停止后续分析，额度不足停止，不自动转付费。模型结果保留可见事实、推断、限制与交叉验证，人工修正同步云端，原始自动结果继续留存。
6. 人工复核可以修改日期、车间、工序、关联日报、场景、标签、说明和证据类型，也可以标为关键证据或忽略。
7. 无论置信度高低，AI 推断都不能单独作为停工、设备到货或质量验收结论；最终状态必须人工确认或有其他直接记录支撑。

手工和表格日报保存在 IndexedDB 轻量缓存；PDF 批次采用下述云端优先顺序，把原始 PDF、结构化日报、图片和导入审计保存到 Supabase 后再落本地元数据，以便跨设备访问。

### PDF 与图片存储顺序

PDF 导入采用云端优先事务流程，避免浏览器存储配额中断上传：

1. 已配置云端时必须先登录才可导入 PDF；未配置云端的开发/离线模式可以本机导入，原始文件和图片保存在 IndexedDB。
2. PDF 仅在当前页面内存中解析和预览，不把原始 PDF 或 Base64 图片写入 `localStorage`。
3. 用户确认后，先把原始 PDF 和提取图片上传到私有 `khayrat-reports` bucket；对象路径包含稳定的导入批次 ID。
4. 全部对象上传成功后，以 upsert 方式保存日报、图片元数据和导入审计，再写入不含二进制内容的本地轻量缓存。
5. 部分上传失败时保留当前批次和进度，按钮变为“重试失败上传”；相同批次和对象路径会安全覆盖，不会新增重复统计。
6. 图片展示使用短期签名 URL，重新登录或刷新页面时重新签发；数据库和浏览器元数据中不保存公开图片地址。

旧版本已经存在的浏览器数据不会在启动时被自动清除或迁移到云端。没有云端对象路径的旧图片仍保存在 IndexedDB；只有已上传的图片才以轻量元数据缓存。启动时不会自动上传历史文件。

## 本地数据与防重复规则

- 手工保存、CSV/XLSX 导入和 JSON 恢复最终都进入同一个本地数据仓库。
- 活动级业务键为 **日期 + 车间 + 工序 + 活动编号**；没有活动编号时使用设备及原始记录摘要。同日同车间同工序的不同活动会保留，完全相同的活动才会跳过。
- “备份数据”下载包含格式版本、日报记录及图片证据的 JSON 文件；“恢复备份”只接受这一格式。
- IndexedDB 和 `localStorage` 都不是云存储。清理站点数据、重装浏览器或更换电脑都可能丢失数据，日常使用应定期备份。

## 数据口径修正

- 项目总体计划和实际进度只在存在有效 `WBS权重` 时计算加权值；没有权重时总体值显示为空，仅展示车间/工序分项，简单平均不再冒充正式总体进度。
- 工程量严格按“车间 + 工序 + 工作量单位”分组，m³、t、项等不同单位不会相加。
- `人员口径` 区分项目总人数与车间施工人数；项目人数趋势只读取明确的“项目总人数”；缺失或冲突时显示未知，`工种`保留作进一步资源分析。
- 停工需要日报明确标注停工，或同时满足进度无变化、工程量无变化且该工序人员为零；仅仅当日混凝土为零不会再判为停工。

## Google Drive 只读同步方案

代码中已提供 `GoogleDriveReadOnlyAdapter` 接口骨架，但界面暂不启用账号授权。计划流程是：

1. 管理员在 Google Cloud Console 创建 **OAuth 2.0 Web Client**，配置实际部署域名，并在运行环境中提供 Client ID 和项目文件夹 ID。
2. 前端使用 Google Identity Services 弹出授权，仅请求 `drive.readonly` 最小权限；用户在 Google 官方页面登录，应用不接触账号密码。
3. 通过 Drive API 查询指定文件夹的 CSV/XLSX 文件，用 `id + modifiedTime + md5Checksum` 判断新增或变化文件。
4. 下载内容后复用现有 CSV/XLSX 适配器、标准化、校验和业务键去重流程。
5. 访问令牌只保存在页面运行内存中，退出或过期后重新授权；Client Secret、刷新令牌、账号密码和私有凭据不得写入前端或仓库。

双向写回、后台定时同步和冲突解决不在当前阶段范围内。

## 计算口径

- **总体进度**：只对存在正数 WBS 权重的最新活动记录加权计算；缺少权重时显示空状态。
- **人员数量**：项目趋势只读取“项目总人数”口径，同一日期取中方/属地人数的项目级记录，避免车间和工种明细重复累加。
- **完成量**：按车间、工序和单位分别统计当日及累计值，不对不同单位求和。
- **关键节点滞后**：最新实际进度比计划进度低至少 5 个百分点。
- **连续停工**：同一“车间 + 工序”连续至少 **3 个有效日报日**明确标注停工，或同时满足进度无变化、工程量无变化且人员为零。仅工程量为零不会触发。这里的“连续”指连续上报记录，不推断缺失日期。

CI 或测试电脑需要能够安装 Chromium。本项目不会用 HTTP 冒烟测试或 `node --check` 冒充浏览器测试；若环境没有浏览器，必须将 E2E 结果明确报告为“未执行”。

`.github/workflows/ci.yml` 会在 PR 更新及 `master` 推送时分别执行单元/集成测试、生产构建和真实 Chromium E2E。建议将这两个 job 设置为合并前的必需检查，避免冲突解决后未经验证直接合并。

### 使用真实 PDF 验收

1. 准备一份可搜索文字的多页中英文日报，以及一份扫描型日报；备份敏感信息后再测试。
2. 在“日报数据导入”选择 PDF，先检查导入预览中的来源、日期、车间、工序、重复项和错误，不确认则不会写入。
3. 导入后在历史日报逐页核对原文片段、人员数量、工程量单位和数值；缺失字段应显示待复核。
4. 在“图片证据”核对照片页码、编号、邻近说明和日报关联。未配置视觉后端时页面必须提示未启用真实视觉识别。
5. 扫描页只有在用户授权并配置 OCR Provider 后才允许发送处理；当前仓库不包含 OCR 服务或任何外部 API 密钥。
6. 测试完成后导出 JSON 备份，再恢复到新的浏览器配置，核对日报和图片数量。

## 尚未实现

- OCR Provider 已定义授权和后端边界，但仓库未内置 OCR 模型或服务；扫描型 PDF 在未配置时会标记未授权 OCR。
- 完全不支持当前 PDF.js 的旧浏览器仍会降级到内置解析器，并显示人工复核警告。
- 复杂跨页/合并单元格表格和少数字体编码仍可能需要人工复核。
- JPEG/Flate 图片已通过浏览器测试；蒙版、矢量图、重复平铺组合和未提供的复杂编码仍需实际日报验收。
- 真正读取图片像素的高级视觉模型；当前版本为规则、邻近文字和人工标注工作流。
- Google Identity Services 的实际 UI 授权和 Google Drive 在线同步（当前只有可测试的只读适配器骨架）。
- 精细项目角色、审批流及多人同时编辑的冲突解决；生产权限以现有数据库实际 RLS 为准，历史初始化 SQL 不是生产权限的完整描述。
- 从 Primavera P6 / Microsoft Project 自动导入 WBS 基准；当前可通过日报字段或模板提供 WBS 权重。
- XLSX 解析器目前读取首个工作表，不处理宏、公式计算结果之外的公式求值、合并单元格语义和旧版 `.xls`。

日报缺失值保留为空/`null`，`fieldStatus` 区分 reported / not-reported / uncertain；`reviewFields` 列出需要复核的字段。人员口径未报告时不会冒充项目总人数。两份日报出现不同单位、匹配歧义或相互冲突的变化信号时，不给出确定改善/恶化结论。
