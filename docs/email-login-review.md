# 当前页面验证邮箱登录链接

## 问题与行为

邮件链接在另一个浏览器打开后，只会登录那个浏览器。重复打开已经使用的链接也不能让当前浏览器登录。此次在现有邮箱登录弹窗中增加接收邮箱和未打开链接的验证入口；验证成功后，仍由 Supabase SDK 保存、恢复和续期此浏览器的会话。

只接受当前 Supabase 项目的 HTTPS `/auth/v1/verify` 邮件链接，以及 email/magiclink 类型。链接中的 redirect_to 不被执行；其他项目、注册、密码恢复、重复参数及 URL 凭据被拒绝。token_hash 仅通过 Supabase SDK 的 verifyOtp POST 验证，不写入地址栏、日报或日志。输入提交、取消或 Escape 后清空。随后通过 getUser 验证已确认邮箱并匹配用户输入的接收邮箱；验证前不会向应用发布会话，失败清除本地会话并显示不包含上游详情的错误。后端身份、白名单、RLS 和私有文件校验继续生效。

这是一次正常邮箱验证入口，不能解决 Supabase 邮件发送限额。邮件链接已打开、过期或邮箱不一致时，需要新的未打开链接。不要在聊天、PR 或仓库中提供链接、验证码或密钥。
