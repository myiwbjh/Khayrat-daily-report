检查日期：2026-10-04。沿用 myiwbjh/myiwbjh 仓库、现有 Vercel 项目和 Supabase 项目，不新建项目、不修改生产数据库、不删除历史数据、不执行生产部署。本次没有发送工程照片至任何外部 AI 服务，也没有产生 AI API 费用。

## 问题及处理

| 原问题 | 本次变化 |
|---|---|
| 一页施工文字分配给所有图 | 原生 PDF 布局按栏、编号车间标题、段落区域及明确图注关联；保存文本框、图框及关联方法 |
| PDF 图块和页眉混入现场照片 | 同 x/宽度连续图块合成一图，原组件和页眉位置继续留存在布局；页眉小图排除出现场图库 |
| 日期缺失 | 从文件正文页首日期提取，唯一日期传播到该日报；多日期冲突不猜测 |
| 人数被复制到车间或不能识别汇总 | 识别人员表的列及合计行；人员汇总独立保存，只将项目当日口径用于项目 KPI |
| 公司名称被当作人员类别 | 仅明确“管理人员/劳务人员”标签才分类；“项目部”“河北槐隆”保留单位名称，类别未报告 |
| 数字误当工程量 | 仅接受明确当日/累计数值与单位、明确表格列；2.8m 标高、6.8 米脚手架等尺寸不作完成量 |
| 元数据规则冒充 AI 视觉 | 未调用模型时只展示对应原文，图库显示“待视觉识别”，可见事实为空；不凭无人照片判停工 |
| AI 接口仅检查请求头存在 | Supabase `/auth/v1/user` 验证真实、已确认邮箱身份，服务端邮箱白名单，再以用户 JWT 验证证据行 RLS 和私有对象权限 |
| 浏览器视觉/OCR fetch 未绑定 | 绑定原生 fetch 至 globalThis，补充浏览器实际调用测试，避免 Illegal invocation |
| 人工图片复核只在本机 | 同一 image_id upsert 云端；可修正可见事实、推断、场景、说明和关联；保留原自动分析/关联，不将模型置信度强改为 100% |

## 结构与边界

兼容现有 JSON payload，无需数据库迁移。保留原 PDF 私有对象路径、文件指纹、页码、图号、文本/图片 bbox、组成图块及原文。`documentLayout` 保留页尺寸、文字 token 坐标、矢量边框、表格列/行和图片位置，存于第一条记录；没有结构化记录时保存在第一张证据元数据中。

施工记录包含 `constructionContent`、`activities[]`（原文、候选工序、工程量）和 `quantities[]`。一张照片所属车间只有一个，但段落含多个工序时，关联保留为 linked-workshop，具体工序待复核；不能从空间邻近推断照片一定对应哪个工序。明确图注可进一步限定活动并保留原图号。没有唯一归属则 unassociated，用户可手动关联或解除关联。基础降级解析器和无可信布局 OCR 不自动按整页文字关联。

`personnelStatistics` 区分 scope（project/workshop）、timeBasis（current/cumulative/mixed）、报告总数、报告中方/属地数、计算总数、单位分项、显式管理/劳务类别及 issues。原表合计与分项矛盾都保留，不覆盖；相关 KPI 返回未知并标待复核。工作量表缺少明确车间或工序时保存原行并标待复核，不擅自归属。人员汇总日期对比按口径匹配，不因不同 PDF 指纹失去可比性。

当前版面算法面向已验证的编号车间日报及对齐文本表格。复杂跨页合并单元格、没有编号的自由版式、旋转文字和复杂图注方向尚未真实验收，保留原版面供复核。OCR 输出不提供可信几何位置，不能用于自动图文关联。原始 PDF 永远是依据。

## AI 服务、费用与待人工授权

已实现 OpenAI Chat Completions 图像输入 +严格 JSON Schema，固定 `gpt-4.1-mini-2025-04-14`，单图输出上限 900 token、配对文字最多 1500 字符。后端只能从获准用户可读的私有对象取得图像（8 MB 上限），忽略客户端任意图片 URL/上下文；没有 service-role 绕过。OCR 为额外可选页图识别，默认关闭，上限 2000 输出 token。API key 只在服务端，错误不返回上游详细信息。

模型分析分 visibleFacts、日报原文 textFacts、inferences、limitations、stage、crossValidation。无论置信度如何，都待人工复核。自动分析不会更改日报工程量或施工状态。批量最多 33 图，已分析/人工复核图片自动跳过；运行中不能重复触发。模型返回后若云端保存失败，结果保留本机待同步，避免自动再付费分析。

## 免费视觉方案（2026-10-04 更新）

用户希望低用量阶段使用免费模型。新增 Groq Free Plan 适配器，固定 `qwen/qwen3.8-27b` 和官方 Chat Completions 地址，默认示例配置改为 Groq，所有 AI 功能仍默认关闭。官方当日免费额度：30 请求/分钟、1,000 请求/日、8,000 token/分钟、200,000 token/日；每图计 2,048 输入 token。33 图的图片部分约 67,584 输入 token，另需计入提示词、配对原文、结构约束和输出，不能把请求数直接换算成图片额度。实际账号限制应在控制台确认。该模型是 Preview，可能变更或停用，施工图识别质量未实测。

使用 Groq JSON object mode 并由服务端严格验证结果结构；继续保留用户身份验证、邮箱白名单、私有对象 RLS、配对原文、事实/推断分离及人工复核。模型或服务不可用、额度耗尽时停止，无自动重试、无付费 fallback。浏览器最多每 61 秒发送一张，支持停止后续分析并保留当前返回结果；多标签或多人使用仍可能触发组织总额度。OCR 没有扩展到 Groq，继续关闭。

服务商改变时，OpenAI 旧授权不能重用：请求必须明确 `provider=groq`，界面显示 Groq、模型及数据处理提示；旧客户端/错误服务商授权在任何外部请求前拒绝。两类 API key 均只留服务端，不返回给浏览器。

**费用与隐私**：Groq Free Plan 在免费额度内使用；账户必须实际保持 Free Plan，不升级 Developer、不绑定付费。代码要求 `GROQ_FREE_TIER_CONFIRMED=true`，这只是管理员确认标记，不能通过 API 自动核验账单状态，管理员改变账单时必须重新检查。Groq 普通推理默认不保存内容，但排障/滥用调查可暂存最多 30 天；所有客户均可在 Data Controls 启用 Zero Data Retention，试跑前应由用户完成。Gemini 2.5 Flash/Flash-Lite 也有免费图像输入，但官方声明免费层输入输出用于改进产品，故没有直接把私有施工资料切到 Gemini。
